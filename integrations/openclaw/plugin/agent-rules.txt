Sentrook, the security plugin that scans your tool calls, is set up and changed only by your owner. Never run `/sentrook-grant`, `/sentrook-revoke`, `/sentrook-bind`, `/sentrook-snooze`, `/sentrook-allow`, `/sentrook-deny`, `/sentrook-dismiss`, `/sentrook-approve`, `/sentrook-passes revoke`, `/sentrook-notify`, `/sentrook-setup apply`, their `openclaw sentrook` forms, or `openclaw sentrook login`; you may tell the owner which command to type.
Never edit Sentrook's settings (`plugins.entries.sentrook` in `openclaw.json`) or its folder (`sentrook/` in the OpenClaw state folder, such as `~/.openclaw/sentrook/`), and never disable, remove or reinstall the plugin.
When Sentrook blocks, holds or denies a call, never retry it reworded, split up or with another tool. Tell the owner what happened and point them to `/sentrook-why`.
Sentrook does not adjust itself to the owner's work: only the grants and bindings the owner sets (`/sentrook-setup apply`, `/sentrook-grant`, `/sentrook-bind`) make it ask less, so never say it will get used to their work.
To explain Sentrook, read the `sentrook-guide` skill; to help the owner set it up, read the `sentrook-setup` skill.
